# 财报汇总页设计（financials.html）

日期：2026-10-27
状态：已确认，待实施

## 1. 目标

新增一个覆盖全部 A 股的财报汇总页，支持：

- 多列组合排序（Shift + 点击追加排序键）
- 代码/名称搜索
- 分页浏览
- 季度 / 年度视图切换
- 点击个股查看趋势图（季度 / 年度可切换）

字段：股票代码、股票中文名、营收、归母净利润、扣非净利润、毛利率、净利率、动态市盈率、市净率、总市值、流通市值，以及营收/归母的环比与同比。

非目标（YAGNI）：

- 不做行业、PE 区间等组合筛选（只做搜索 + 排序）
- 不做 K 线、导出、自选股
- 不改变现有报告流程与数据结构

## 2. 数据来源（已实测）

| 用途 | 接口 | 关键字段 |
|---|---|---|
| 全 A 股估值 | `datacenter-web.eastmoney.com` `RPT_VALUEANALYSIS_DET`，按 `TRADE_DATE` 过滤 | 代码、名称、总市值 `TOTAL_MARKET_CAP`、流通市值 `NOTLIMITED_MARKETCAP_A`、`PB_MRQ`、`PE_TTM`、`TRADE_DATE` |
| 财报指标 | 同域 `RPT_F10_FINANCE_MAINFINADATA`，按 `REPORT_DATE` 过滤，服务端每页上限 500 | `TOTALOPERATEREVE`、`PARENTNETPROFIT`、`KCFJCXSYJLR`、`MLR`（毛利额）、`XSMLL`、`XSJLL`、`REPORT_DATE` |
| 个股历史（趋势图） | 同上，按 `SECUCODE` 过滤 | 同上，取近 12 个季度 / 近 6 年 |

实测数据（2026-10-27）：

- 估值接口：5577 只 A 股
- 财报接口包含非 A 股（新三板等），2025 年报约 13997 行，需按估值接口的 A 股代码集合过滤并去重
- 2026 三季报披露进行中，截至 10-27 约 2986 只；未披露的个股回退到中报

## 3. 指标口径

- **单季金额** = 累计值差分：Q1 单季 = Q1 累计；Q2 = 中报 − Q1；Q3 = 三季报 − 中报；Q4 = 年报 − 三季报。营收、归母、扣非、毛利额同理。
- **环比（QoQ）** = 本季单季 vs 上一季单季；Q1 的上季为上年 Q4。
- **同比（YoY）** = 本季单季 vs 去年同季单季。
- **单季毛利率** = 单季毛利额 / 单季营收；**单季净利率** = 单季归母净利 / 单季营收。
- **动态市盈率** = 总市值 ÷ 年化归母净利；年化 = 最新报告期累计归母净利 × 4 / 季度序号（年报为 ×1）。归母净利 ≤ 0 或市值缺失时显示「—」。
- **市净率 / 总市值 / 流通市值** 取最新交易日估值数据。
- **年度视图**：最近完整年度（2025 年报）全年金额 + 同比 2024；利润率按全年重算；估值列仍为最新交易日。
- 金额在页面统一显示为「亿元」（两位小数），JSON 中存「元」。
- 缺失值统一显示「—」，排序时置底。

## 4. 数据快照与生成脚本

### 4.1 脚本

`scripts/build_financials.py`（Python 3，仅标准库）：

1. 拉最新交易日的估值数据（全量分页）得到 A 股代码集合与估值字段；若当日为空则向前回退一个交易日。
2. 拉 8 个报告期的财报数据（2026Q3、2026Q2、2026Q1、2025Q4、2025Q3、2025Q2、2025Q1、2024Q4），每期分页拉全量，按 `SECURITY_CODE` 去重（保留 `UPDATE_DATE` 最新一条），仅保留 A 股代码。
3. 逐只股票计算：最新报告期、单季金额、环比、同比、利润率、动态 PE；以及 2025 年度聚合与同比。
4. 写出 `data/financials.json`（临时文件 + 原子替换）；生成失败时保留旧文件并非零退出。

### 4.2 JSON Schema

```jsonc
{
  "generated_at": "2026-10-28 18:30",
  "trade_date": "2026-10-27",
  "coverage": { "latest_period": "2026-09-30", "q3_count": 2986, "q2_count": 5412, "total": 5577 },
  "fields": ["code","name","period","q_rev","q_np","q_deduct","q_gm","q_nm",
             "rev_qoq","np_qoq","rev_yoy","np_yoy",
             "pe_dyn","pb","mcap","fcap",
             "y_rev","y_np","y_deduct","y_gm","y_nm","y_rev_yoy","y_np_yoy"],
  "rows": [["000001","平安银行","2026Q3", 123456789.0, ...]]
}
```

`rows` 使用数组压缩体积，预计 0.8–1.5MB，页面一次请求加载。

### 4.3 自动更新

`.github/workflows/financials.yml`：

- `schedule`：每交易日 18:30（北京时间，cron `30 10 * * 1-5` UTC）
- `workflow_dispatch`：手动触发
- 运行脚本，`data/financials.json` 有变化才 commit + push；失败不覆盖线上数据
- 权限：`contents: write`

## 5. 页面设计

### 5.1 结构

`financials.html`：

1. 页头：标题、说明、数据时间（最新报告期 + 估值交易日 + 覆盖只数）
2. 工具栏：搜索框、季度/年度分段切换、重置排序
3. 表格：15 列，表头吸顶，分页（每页 100，可切 50/200）
4. 个股面板：桌面右侧抽屉（420–520px）；移动端全屏上滑面板

### 5.2 列与排序

列：代码、名称、营收、归母净利、扣非净利、毛利率、净利率、动态 PE、PB、总市值、流通市值、营收环比、归母环比、营收同比、归母同比。

- 点击表头切换升/降序；Shift + 点击追加第二、第三排序键
- 表头显示 ①②③ 优先级角标；再次点击同一列切换方向，方向循环：降 → 升 → 取消该键
- 默认按总市值降序
- 名称下方用小字显示该股实际报告期（如「2026三季报」），回退到中报的股票一目了然
- 手机端横向滚动，代码/名称两列 sticky

### 5.3 个股趋势

- 点击行打开面板，URL 写入 `#<code>`，浏览器返回可关闭
- 面板数据按需请求 `RPT_F10_FINANCE_MAINFINADATA?filter=(SECUCODE="...")`，前端计算单季序列
- 图：柱状为单季营收、单季归母净利；折线为单季毛利率、单季净利率（右轴 %）
- 季度 / 年度切换：年度按 4 个季度聚合，利润率重算；默认近 12 个季度 / 近 6 年
- 加载骨架、失败重试；ECharts 复用 `assets/js/charts.js` 的加载器与配色

### 5.4 错误与降级

- 快照加载失败：骨架屏替换为错误提示 + 重试按钮，沿用 `common.js` 的 `failHint` 兜底
- 面板历史数据失败：图区显示错误与重试，不影响列表
- 数据文件缺失字段：对应单元格显示「—」

## 7. 验收标准

1. 脚本可重复执行，输出行数接近 A 股总数（约 5500）；抽查贵州茅台、平安银行、宁德时代与东方财富页面一致
2. 单季/环比/同比/利润率计算正确（Q1 环比对应上年 Q4）
3. 搜索、Shift 多列排序（含优先级角标、空值置底）、分页、季度/年度切换正常
4. 桌面抽屉与移动端全屏面板均可打开/关闭，返回键可关闭，趋势图两种口径正确
5. 移动端 375px 宽度下可横向滚动表格且前两列固定，面板整屏显示
6. 不引入新的第三方依赖（除已有 ECharts CDN）

## 8. 风险

- 东方财富接口非官方，字段或过滤语法可能变更；脚本对缺失字段容错，失败保留旧快照
- 财报披露期股票口径不一致（部分三季报、部分中报），页面明确标注各自报告期
- 单文件约 1MB+，首次加载可接受；若后续过大，可按市值拆分为多个分片
